Azure Storage Security with Service Endpoints and Network Security Groups

Project Overview

This project demonstrates how Azure Storage can be secured using Azure Service Endpoints, Network Security Groups (NSGs), and Storage Account network rules. The solution restricts storage access to trusted virtual network subnets, ensuring that storage traffic remains on Microsoft's private Azure backbone while significantly reducing exposure to unauthorized access and data exfiltration.

Business Scenario

A fictional organization stores confidential business documents within Azure Blob Storage. To satisfy internal security policies and compliance requirements, access to the storage account must be restricted to workloads running inside approved Azure virtual networks. Internet-based access should be blocked while maintaining secure connectivity for authorized resources.

Security Objectives

  • Protect Azure Storage from unauthorized network access.
  • Restrict storage communication to approved Azure Virtual Network subnets.
  • Configure Azure Service Endpoints for secure private connectivity.
  • Implement Network Security Groups to strengthen network segmentation.
  • Validate that only authorized virtual machines can access storage resources.
  • Demonstrate Azure cloud security best practices and defense-in-depth.

Implementation Overview

The following implementation phases document the complete deployment, configuration, testing, and validation of Azure Storage security controls. Each phase demonstrates a practical security task together with supporting evidence, validation results, and the security impact of the configuration.

Implementation Phase 1 – Deploy Azure Storage Account

Objective

The first phase of the project focused on deploying an Azure Storage Account, which serves as the central repository for enterprise data. Azure Storage provides highly available, scalable, and durable cloud storage services for blobs, files, queues, and tables. Establishing the storage account provides the foundation upon which additional security controls such as Service Endpoints, Storage Firewalls, and Network Security Groups can be applied.

Implementation

An Azure Storage Account was created using the Azure Portal with the appropriate subscription, resource group, region, performance tier, and redundancy options. The storage account was configured to support secure enterprise workloads while remaining ready for subsequent network security configuration.

With the storage service operational, the next phase focuses on configuring Azure Service Endpoints to restrict access through trusted virtual network subnets and eliminate unnecessary exposure to public networks.

Implementation Phase 2 – Create the Azure Virtual Network

Objective

After deploying the Azure Storage Account, the next step was to create an Azure Virtual Network (VNet) that would provide a secure, isolated networking environment for Azure resources. The virtual network serves as the foundation for implementing Service Endpoints and Network Security Groups, enabling secure communication between virtual machines and Azure Storage over Microsoft's private backbone network.

Implementation

A new Azure Virtual Network was created with dedicated address spaces and subnets to support secure workload isolation. The subnet was designed to host virtual machines that would later be granted controlled access to the Azure Storage Account through Azure Service Endpoints.

Implementation Phase 3 – Configure the Network Security Group

Objective

With the Azure Virtual Network successfully deployed, the next phase focused on implementing a Network Security Group (NSG). NSGs provide stateful packet filtering for Azure resources by controlling inbound and outbound network traffic through security rules. This layer of protection helps enforce network segmentation and limits communication to only authorized traffic.

Implementation

A Network Security Group was created and associated with the virtual network subnet hosting the virtual machine. Security rules were configured to allow required management traffic while restricting unnecessary network access. This ensured that only approved communication paths were available before connecting the subnet to the Azure Storage Account.

Figure 4. Network Security Group configured and associated with the Azure subnet to control inbound and outbound network traffic.

Network Security Configuration

Configuration Purpose
Network Security Group Provides network-level traffic filtering.
Subnet Association Applies security rules to all resources within the subnet.
Inbound Rules Allow only required management and application traffic.
Outbound Rules Restrict unnecessary outbound communication.

Why This Phase Matters

Network Security Groups form a critical layer of defense in Azure by controlling traffic before it reaches protected resources. Even if a resource exists within a trusted virtual network, NSGs ensure that communication follows defined security policies, reducing the risk of unauthorized access and limiting potential lateral movement within the environment.

Security Benefits

  • Filters inbound and outbound network traffic.
  • Supports network segmentation through subnet-level security.
  • Reduces the attack surface by limiting unnecessary connectivity.
  • Helps prevent unauthorized lateral movement.
  • Provides centralized management of network security rules.
  • Strengthens defense-in-depth alongside Azure networking controls.

Outcome

The Network Security Group was successfully deployed and associated with the target subnet. Traffic filtering policies were now in place, providing a secure network foundation for enabling Azure Service Endpoints in the next phase of the project.

Implementation Phase 4 – Configure Azure Service Endpoints

Objective

With the Azure Virtual Network and Network Security Group in place, the next phase was to enable Azure Service Endpoints. Service Endpoints extend the identity of the virtual network to supported Azure services, allowing resources within approved subnets to communicate securely with Azure Storage over Microsoft's private backbone network rather than the public internet.

Implementation

Azure Service Endpoints for Microsoft.Storage were enabled on the designated subnet within the virtual network. This configuration allowed the subnet to establish trusted connectivity with the Azure Storage Account, forming the basis for enforcing storage firewall rules in the next phase.

  • Strengthens defense-in-depth through network-based access controls.

Outcome

Azure Service Endpoints were successfully enabled for the designated subnet, creating trusted network connectivity to the Azure Storage Account. The environment was now ready to configure Storage Firewall rules that would limit storage access exclusively to approved virtual network resources.

Implementation Phase 5 – Configure Azure Storage Firewall Rules

Objective

The final implementation phase focused on restricting access to the Azure Storage Account using Storage Firewall rules. While Azure Storage is accessible over public endpoints by default, firewall rules allow organizations to limit access exclusively to approved virtual networks and subnets. This significantly reduces the attack surface and helps prevent unauthorized access to sensitive data.

Implementation

The Azure Storage Account networking configuration was updated to deny access from untrusted networks while allowing connectivity only from the subnet where Azure Service Endpoints had been enabled. By combining Storage Firewall rules with Service Endpoints, only trusted Azure resources within the approved virtual network could successfully communicate with the storage account.

Figure 6. Azure Storage Firewall configured to allow access only from approved virtual network subnets.

Why This Phase Matters

Storage Firewalls provide an additional layer of protection by ensuring that even if an attacker knows the storage account endpoint, access requests from unauthorized networks are denied. Combined with Azure Service Endpoints, this creates a defense-in-depth architecture where both the network path and the storage service enforce access restrictions.

Security Benefits

  • Restricts Azure Storage access to trusted virtual networks.
  • Blocks unauthorized public network connections.
  • Reduces the risk of data exposure and exfiltration.
  • Works together with Service Endpoints for layered security.
  • Improves compliance with enterprise security policies.
  • Strengthens the overall cloud security posture.

Outcome

Azure Storage Firewall rules were successfully configured to restrict access to approved virtual network resources. Together with Azure Service Endpoints and Network Security Groups, the storage account was protected using multiple layers of network security, providing a secure foundation for validating authorized and unauthorized access in the next stages of the project.

Lessons Learned

This project demonstrated that securing Azure Storage extends beyond protecting the data itself. Effective storage security requires a layered approach that combines network isolation, trusted connectivity, and access restrictions to minimize exposure to unauthorized users and services.

Implementing Azure Service Endpoints together with Storage Firewall rules highlighted the importance of controlling where traffic originates, ensuring that only workloads within approved virtual networks could communicate with the storage account. This approach significantly reduces the risk of unauthorized network access and data exfiltration.

The project also reinforced the value of defense-in-depth by combining Azure Virtual Networks, Network Security Groups, Service Endpoints, and Storage Firewall rules into a unified security architecture that aligns with Microsoft Azure security best practices.
